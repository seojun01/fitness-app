# Research: 운동 가이드 (텍스트)

**Feature**: `002-exercise-guide` | **Date**: 2026-11-14 | **Plan**: [plan.md](./plan.md)

> **범위 변경 이력 (2026-11-14)**: 처음에는 인체 모델(관절 17개, FK)로 2D 동작 애니메이션과 3D 보기를 그리기로 했다(옛 G1~G5·G9). 사용자가 3D를 뺐고, 이어서 동작 그림과 근육 지도도 필요 없다고 해 **텍스트 가이드만** 남겼다. 기반 작업 13개로 만든 뼈대·투영·렌더러 코드는 지운다. git 기록(커밋 `1e1beb3`, `d51bfae`)에 남아 있으니 다시 필요하면 거기서 되살린다.

각 항목은 결정 / 근거 / 대안 순서다.

### G4'. 근육 목록 (유지, 그리기 정보 제거)

- **결정**: 17종(대흉근, 광배근, 승모근, 능형근, 전면·측면·후면 삼각근, 이두근, 삼두근, 전완근, 복직근, 복사근, 척추기립근, 둔근, 대퇴사두근, 햄스트링, 종아리)을 `shared/muscles.ts`에 한국어 이름과 함께 둔다. 강조할 뼈 구간 정보는 지운다.
- **근거**: 기본 가이드와 노트가 같은 목록을 써야 검증과 표시가 일관된다.

### G5'. 가이드 데이터 로딩과 오프라인 (유지)

- **결정**: `shared/guides.ts`를 클라이언트에서 `import()`로 지연 로딩한다. 별도 청크로 나오고, 빌드가 사전 캐시 목록에 넣어 서비스 워커가 설치할 때 미리 받는다.
- **근거**: FR-011(항상 오프라인)과 헌법 III(지연 로딩)를 함께 만족한다.

### G6. 가이드 노트: 새 레코드 종류 `guideNote` (유지)

- **결정**: `id`는 종목 id와 같다(1:1). 필드는 `cues[]`, `mistakes[]`, `primaryMuscles[]`, `secondaryMuscles[]`와 공통 필드다. 기본 종목 id면 거부한다(FR-008). 모두 비우면 툼스톤으로 만든다.
- **근거**: 기능 1의 동기화·내보내기·전체 삭제를 그대로 쓰고, 서버 스키마를 바꾸지 않는다.
- **대안**: 종목 레코드에 넣는 방법은 이름 수정과 노트 수정이 LWW로 서로 덮어써 기각했다.

### G7. IndexedDB 업그레이드와 내보내기 버전 (유지)

- **결정**: DB 버전 2에서 `guideNotes` store를 추가하고, 업그레이드할 때 동기화 cursor를 0으로 되돌린다. 내보내기 버전 2에서 `guideNotes`를 추가한다.
- **근거**: 업데이트 전 앱은 모르는 `guideNote`를 건너뛰고 cursor만 넘겼을 수 있다. 한 번 전체 pull로 다시 받는다(LWW라 결과는 같다).

### G8. 진입 방식: 대화상자 vs 화면 이동 (유지, 진입점 갱신)

- **결정**: 진행 화면(종목 이름 옆 ⓘ)과 종목 선택(종목마다 "가이드")에서는 `<dialog>`로 연다. 가이드 탭에서는 `#/guides/:exerciseId` 전체 화면으로 연다.
- **근거**: 대화상자는 원래 DOM을 그대로 두므로 입력값·스크롤·타이머가 유지된다(FR-003, SC-001).

### G11. 기본 가이드 문구 작성 원칙 (신규)

- **결정**:
  - 요점은 짧은 명령문 3~5개로, 준비 자세 → 동작 → 호흡·속도 순으로 쓴다.
  - 실수는 초보자에게 흔한 것 2~4개를 쓴다.
  - 근육은 일반적인 운동학 분류를 따른다.
  - 의학적 단정(치료·부상 보장)은 쓰지 않는다. 화면 아래에 안전 안내를 둔다.
- **근거**: 스펙 가정(의학적 조언 아님)과 SC-004(읽고 설명할 수 있음)를 지키기 위해서다.
