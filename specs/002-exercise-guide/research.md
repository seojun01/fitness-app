# Research: 운동 가이드

**Feature**: `002-exercise-guide` | **Date**: 2026-11-14 | **Plan**: [plan.md](./plan.md)

기능 1의 결정(R1~R19, `specs/001-routine-workout-logging/research.md`)은 그대로 유효하다. 아래는 이번 기능에서 새로 정한 것이다. 각 항목은 결정 / 근거 / 대안 순서다.

---

### G1. 인체 모델: 관절 17개 뼈대 + 정방향 운동학(FK)

- **결정**:
  - 관절은 골반(루트)·허리·가슴·목·머리, 좌우 어깨·팔꿈치·손목, 좌우 고관절·무릎·발목으로 17개다(몸통 5 + 팔 6 + 다리 6).
  - 뼈 길이는 평균 성인 비율로 고정하고, 키 1.0 단위로 정규화한다.
  - 포즈는 "루트 위치(x,y,z) + 루트 회전 + 관절별 회전(굽힘·벌림·비틀기, 도 단위)"이다.
  - FK로 각 관절의 월드 좌표를 계산한다.
  - 관절별 가동 범위를 정의해, 콘텐츠 테스트가 범위를 벗어난 키프레임을 거른다.
- **근거**:
  - 관절 회전으로 정의하면 어느 시점에서 그려도 같은 데이터를 쓴다(종목마다 측면·정면 등 시점만 고른다).
  - 뼈 길이가 변하지 않아 "팔이 늘어나는" 류의 오류가 구조적으로 생길 수 없다.
  - 손가락·발가락·척추 세분은 자세 이해에 필요 없다(YAGNI).
- **대안**:
  - 관절 좌표를 직접 키프레임: 보간 중 뼈 길이가 바뀌어 기각했다.
  - 외부 모션 캡처(BVH): 데이터를 구해야 하고 Q1 결정(앱이 직접 만든다)과 어긋나 기각했다.

### G2. 렌더링: Canvas 2D + 직접 직교 투영 (그리기 라이브러리 없음)

> **2026-11-14 변경**: 사용자 결정으로 3D 보기(원근 투영, 시점 돌리기)를 범위에서 뺐다. 아래의 3D 관련 내용은 기록으로만 남기며, 구현은 종목별 고정 시점의 직교 투영만 한다. 원근 투영 코드는 넣지 않는다(YAGNI).

- **결정**:
  - 2D 보기는 종목별 기본 시점(대개 측면)의 직교 투영이다.
  - ~~3D 보기는 시점을 돌릴 수 있는 원근 투영이다~~ (변경으로 제외).
  - 몸은 "굵은 둥근 선분(캡슐) + 관절 원 + 머리 원"으로 그린다.
  - 선분은 카메라 깊이 순으로 정렬해 뒤→앞으로 그린다(화가 알고리즘).
  - 기구(바벨 등)도 같은 방식으로 그린다.
  - 기기 픽셀 비율(devicePixelRatio)에 맞춰 선명하게 그린다.
- **근거**:
  - 선분 20개 수준이라 Canvas 2D로 60fps가 충분하다.
  - three.js(약 600KB)를 넣으면 런타임 의존성 0 원칙(헌법 V, 기술 제약)과 초기 성능을 해친다.
  - 대체가 필요한 경우는 canvas 미지원 하나뿐이다. 그때는 동작 설명 글과 텍스트 가이드를 보여 준다.
- **위험**: 선분 단위 깊이 정렬이라 팔이 몸통을 관통하는 순간 앞뒤가 잠깐 틀릴 수 있다. 단순한 마네킹 표현이라 허용한다(스펙 가정).
- **대안**:
  - three.js·babylon: 의존성과 번들 크기 때문에 기각했다.
  - 직접 WebGL: 셰이더·버퍼 관리가 과하고, WebGL 컨텍스트 손실을 처리해야 해 기각했다.
  - SVG: DOM 요소를 매 프레임 갱신하면 모바일 성능이 떨어지고 깊이 정렬이 번거로워 기각했다.

### G3. 동작 정의: 템플릿 + 매개변수

- **결정**:
  - 동작 템플릿은 약 12개다.
    - 수평 누르기(벤치·인클라인·푸시업·딥스)
    - 수직 누르기(오버헤드·덤벨 숄더 프레스)
    - 플라이·크로스오버
    - 수직 당기기(풀업·랫 풀다운)
    - 수평 당기기(바벨 로우·시티드 로우·페이스 풀)
    - 스쿼트·레그 프레스
    - 힌지(데드리프트·루마니안)
    - 런지
    - 무릎 굽힘·폄(레그 컬·익스텐션)
    - 팔꿈치 굽힘(바벨 컬·해머 컬)
    - 팔꿈치 폄(푸시다운·스컬 크러셔)
    - 레이즈(사이드·프론트)
    - 코어(플랭크·크런치·레그 레이즈·러시안 트위스트)
    - 주기 동작(러닝·사이클·로잉·줄넘기)
  - 각 템플릿은 `(params) → { keyframes, durationMs, view, props }`를 만든다.
  - 매개변수는 몸 기울기(인클라인 각도), 손 간격, 기구 종류, 가동 범위, 템포를 정한다.
  - 키프레임은 2~4개이고 첫 프레임과 마지막 프레임이 같아 이음매 없이 반복된다.
  - 보간은 관절 각도 선형 보간에 이징(sine in-out)을 쓴다. 템포는 "내리기 2 : 올리기 1"처럼 구간마다 다른 시간을 허용한다.
- **근거**:
  - 35개를 하나하나 키프레임으로 만들면 작업량과 오류가 커진다. 템플릿을 공유하면 일관성이 생기고 테스트가 쉬워진다.
- **대안**: 종목마다 수작업 키프레임은 기각했다. 템플릿으로 표현하기 어려운 동작만 템플릿 안에서 예외로 직접 정의한다.

### G4. 근육 강조

- **결정**:
  - 근육 목록은 17종이다: 대흉근, 광배근, 승모근, 능형근, 전면 삼각근, 측면 삼각근, 후면 삼각근, 이두근, 삼두근, 전완근, 복직근, 복사근, 척추기립근, 둔근, 대퇴사두근, 햄스트링, 종아리.
  - 각 근육을 뼈 구간(예: 대퇴사두근 → 허벅지 앞쪽)과 측면(앞·뒤)에 대응시킨다.
  - 주동근은 진한 강조색, 보조근은 옅은 강조색으로 해당 선분 위에 겹쳐 그린다.
  - 그림 옆에 "주동근: 대흉근 · 보조근: 삼두근, 전면 삼각근"을 글로 함께 쓴다. 색에만 의존하지 않는다(FR-004).
- **근거**: 단순 모델에서는 근육 모양 대신 "어느 부위인지"만 전달하면 된다.

### G5. 가이드 데이터 로딩과 오프라인

- **결정**:
  - `shared/guides/*`를 클라이언트에서 `import()`로 지연 로딩한다. esbuild `splitting: true`(ESM)로 별도 청크를 만든다.
  - `scripts/build.mjs`가 빌드 결과 파일 목록(메타파일)을 서비스 워커에 `__PRECACHE__`로 주입한다. 그러면 SW 설치 시 가이드 청크까지 미리 캐시된다.
  - 가이드 목록의 정지 미리보기는 같은 렌더러로 대표 자세를 작은 canvas에 한 번만 그린다.
- **근거**:
  - FR-010(항상 오프라인)과 헌법 III(지연 로딩으로 초기 로딩을 해치지 않음)를 둘 다 만족한다.
  - 해시가 붙은 청크 이름도 빌드가 알려 주므로 목록을 손으로 관리하지 않는다.
- **대안**:
  - 메인 번들에 포함: 가이드 데이터만큼 초기 로딩이 늘어 기각했다.
  - 서버 API로 제공: 오프라인 첫 진입이 불가능해 기각했다.

### G6. 사용자 가이드 노트: 새 레코드 종류 `guideNote`

- **결정**:
  - 레코드 `guideNote`의 `id`는 **종목 id와 같다**(1:1). 서버 `records(type,id)`가 그대로 유일성을 보장한다.
  - 필드는 `cues[]`, `mistakes[]`, `primaryMuscles[]`, `secondaryMuscles[]`와 공통 필드다.
  - 기본 종목 id로 된 노트는 클라이언트와 서버 모두 거부한다(FR-012). 기본 종목 id 목록이 `shared/`에 있어서 가능하다.
  - 모든 칸을 비우면 노트를 툼스톤으로 만든다. 그러면 "가이드 없음" 상태로 돌아간다.
- **근거**:
  - 기능 1의 동기화(멱등 push, LWW, 서버 복원 감지)와 내보내기·전체 삭제 경로를 재사용한다.
  - 서버 SQLite 스키마는 바꾸지 않는다.
- **대안**: Exercise 레코드에 필드를 추가하면 종목 이름 수정과 노트 수정이 LWW로 서로 덮어써 기각했다.

### G7. IndexedDB 업그레이드와 내보내기 버전

- **결정**:
  - `DB_VERSION` 2에서 `guideNotes` store(`byDirty` 인덱스)를 추가한다. 기존 store는 그대로 둔다.
  - 업그레이드할 때 동기화 cursor를 0으로 되돌린다. 업데이트 전 앱이 모르는 `guideNote`를 건너뛰고 cursor만 전진시켰을 수 있어서, 한 번 전체 pull로 다시 받는다(LWW라 결과는 같다. [sync-api-delta](./contracts/sync-api-delta.md#이전-버전-클라이언트와의-호환)).
  - 내보내기 `version: 2`에서 `guideNotes` 배열을 추가한다. v1 필드는 그대로라 v1을 읽던 도구도 나머지를 읽을 수 있다.
- **근거**: 헌법 II(마이그레이션 경로)를 따른다. v1 DB를 가진 기기가 앱을 업데이트해도 데이터가 남는지 E2E·단위 테스트로 검증한다.

### G8. 진입 방식: 시트(대화상자) vs 화면 이동

- **결정**:
  - 세션 진행 화면과 종목 선택 대화상자에서는 가이드를 **시트**(`<dialog>`)로 연다.
  - 종목 선택은 이미 대화상자이므로, 가이드 시트를 그 위에 쌓고 닫으면 종목 선택으로 돌아온다.
  - 가이드 탭과 기록·종목 이력 화면에서는 `#/guides/:exerciseId` 전체 화면으로 연다.
- **근거**: 화면 이동은 세션 화면을 다시 그려 스크롤과 입력 포커스를 잃는다. 시트는 원래 DOM을 그대로 둬 FR-005와 SC-001을 구조적으로 만족한다.

### G9. 동작 줄이기·재생 제어

- **결정**:
  - `prefers-reduced-motion: reduce`이면 자동 재생하지 않고 대표 자세를 그린다. 재생 버튼을 누르면 재생한다(사용자가 명시적으로 원한 경우).
  - 시트를 닫거나 화면을 떠나거나 `visibilitychange`로 숨겨지면 rAF 루프를 멈춘다.
  - 버튼은 "재생/일시정지(aria-pressed)"와 "속도 0.5배/1배"다(3D·시점 버튼은 변경으로 제외).
- **근거**: 접근성(FR-003, FR-015)을 지키고 배터리를 아낀다.

### G10. 테스트 전략

- **결정**:
  - **단위**
    - FK: 뼈 길이 불변, 기준 포즈 좌표
    - 보간: 이징 경계, 키프레임 경계
    - 투영: 정면·측면·후면의 축 매핑, 깊이 순서
  - **콘텐츠 무결성(가장 중요)**
    - 기본 종목 35개 모두 가이드가 있다.
    - 요점은 3~5개, 실수는 2~4개, 근육은 목록 안의 값이다.
    - 모든 키프레임이 관절 가동 범위 안이다.
    - 첫 프레임과 마지막 프레임이 같다.
    - 발이 바닥을 뚫지 않는다(서 있는 동작에 한정한 최소 y 검사).
    - 대체 텍스트가 있다.
  - **계약**: `guideNote` push·pull, 기본 종목 id 거부, 검증 롤백
  - **E2E**: 스토리별, 동작 줄이기 에뮬레이션, 세션 중 열고 닫기에서 입력 보존, 두 기기 노트 동기화, IndexedDB v1→v2 업그레이드
- **근거**: 콘텐츠 오류(가동 범위 밖 관절, 빠진 종목)는 화면으로 일일이 확인하기 어렵다. 데이터 수준에서 자동으로 잡는다.
