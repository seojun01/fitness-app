# Research: 성장 차트·통계

**Feature**: `004-growth-stats` | **Date**: 2026-11-15 | **Plan**: [plan.md](./plan.md)

각 항목은 결정 / 근거 / 대안 순서다.

### S1. 계산 위치: 공유 순수 함수 `shared/growth.ts`

- **결정**: 모든 집계(기간 범위, 요약, 주별·월별 막대, 부위 비중, 종목 추이, PR, 달력)를 `shared/growth.ts`의 순수 함수로 만든다. 입력은 세션 배열·종목 맵·`now`·기간이고, 출력은 표시용 숫자다. `shared/stats.ts`의 `estimate1rm`와 완료 세션 필터(`completedSessions`로 export)를 재사용한다.
- **근거**: 헌법 IV(기록에서만 계산, 테스트 가능). SC-002(100% 일치)를 단위 테스트로 직접 검증할 수 있다. 같은 엡리·완료 세트 규칙을 공유해 진행 화면 "기록"과 숫자가 어긋나지 않는다(FR-010).
- **대안**: 미리 집계해 저장(캐시 레코드)하는 방법은 동기화·삭제 때 어긋날 수 있고, 500세션이면 매번 계산해도 충분히 빨라 기각했다(S7).

### S2. 날짜 기준: 세션 시작 시각의 기기 현지 날짜

- **결정**: 세션이 속한 날짜·주·달은 `startedAt`을 기기 현지 시간으로 바꾼 날짜다. 주는 월요일에 시작한다. 날짜 키는 `YYYY-MM-DD`(현지) 문자열로 다룬다.
- **근거**: FR-014. 밤 11시 50분에 시작해 자정을 넘긴 운동은 시작한 날의 운동으로 보는 것이 자연스럽다. 기존 `relativeDay`도 현지 날짜를 쓴다.
- **대안**: `endedAt` 기준은 자정을 넘긴 운동이 다음 날로 가서 기각했다. UTC 기준은 한국에서 오전 9시 이전 기록이 전날로 가서 기각했다.

### S3. 기간 정의와 비교 기간

- **결정**:
  - 최근 4주 = 오늘을 포함한 28일
  - 최근 3개월 = 오늘을 포함해 달력 기준 3개월 전 다음 날부터
  - 최근 1년 = 같은 방식으로 12개월
  - 전체 = 첫 완료 세션 날짜부터 오늘까지
  - 비교 기간은 시작일 바로 전날에서 끝나고 일수가 같은 기간이다. "전체"는 비교하지 않는다.
  - 기간 선택은 `localStorage['fitness.statsPeriod']`에 기기별로 기억한다(FR-001). 종목 차트도 같은 값을 쓴다.
- **근거**: 스펙 "오늘을 포함해 거꾸로 센다", "바로 앞 같은 길이". 기간 선택은 동기화할 데이터가 아니라 화면 상태라 테마처럼 기기에 둔다.

### S4. 막대 단위: 주별, "전체"가 1년을 넘으면 월별

- **결정**: 막대는 기간과 겹치는 주(월요일 시작)마다 하나다. 기간 밖의 날은 세지 않는다. "전체" 기간이 53주를 넘으면 달별 막대로 바꾸고 제목도 "월별"로 바꾼다. 운동하지 않은 주·달은 0으로 표시한다(FR-003).
- **근거**: 몇 년치 주별 막대는 320px 화면에서 막대가 1px보다 가늘어져 읽을 수 없다(엣지 케이스 "점이 겹치지 않게").
- **대안**: 가로 스크롤 차트는 한눈에 보는 목적에 맞지 않아 기각했다.

### S5. 종목 추이 점과 촘촘할 때 묶기

- **결정**:
  - 점은 세션당 하나다. 같은 세션에 같은 종목이 여러 번 있으면 세트를 합친다.
  - 값: 추정 1RM(세트별 엡리 최대, 소수 1자리), 최고 무게, 세션 볼륨, 총 횟수, 최다 횟수.
  - 기간 안 점이 60개를 넘으면 주별로 묶는다. 묶은 점의 값은 1RM·최고 무게·최다 횟수는 주 최대, 볼륨·총 횟수는 주 최대 세션 값이다. 묶었다는 사실은 차트 아래 글로 알린다.
  - 맨몸 판정: 종목의 `bodyweight` 또는 기간 안 완료 세트의 무게가 모두 0이면 "세션 총 횟수"와 "최다 횟수" 지표만 보인다(FR-007).
- **근거**: 기존 `compare`의 맨몸 규칙과 같다. 60점은 320px 차트에서 점 간격 약 4.5px로 구분 가능한 한계다.

### S6. 개인 최고 기록(PR)

- **결정**: 전체 기간 기준으로 다음 네 가지를 계산하고, 각각 처음 달성한 세션의 날짜·id를 함께 둔다(같은 값이면 먼저 달성한 날).
  - 추정 1RM
  - 최고 무게
  - 최고 세션 볼륨
  - 한 세트 최다 횟수
  
  기간 선택과 무관하게 항상 전체 기록이다. 맨몸이면 1RM·최고 무게 대신 "최고 세션 총 횟수"를 보인다.
- **근거**: FR-009. "개인 최고"는 기간에 따라 바뀌면 의미가 흐려진다.

### S7. 성능: 한 번 읽고 메모리에서 계산

- **결정**: 화면을 열 때 `listAllSessions`·`listAllExercises`를 한 번 읽고, 기간을 바꿀 때는 메모리에서 다시 계산만 한다. 세션 500개 × 종목 6 × 세트 4 수준이면 집계는 수 ms다. E2E에서 `scripts/seed-sessions.mjs`로 500세션을 넣고 1초 안에 그려지는지 확인한다(SC-001).
- **근거**: IndexedDB 읽기가 지배적 비용이다. 이미 기록 화면이 같은 방식으로 빠르다.

### S8. 차트 그리기: 직접 만든 인라인 SVG

- **결정**: `client/src/ui/charts.ts`에 선 차트·세로 막대·가로 막대를 `document.createElementNS`로 그리는 작은 함수들을 둔다(innerHTML 금지 규칙 유지).
  - 색은 기존 CSS 토큰(`--accent` 등)을 쓴다.
  - 축 라벨과 최댓값 눈금 2~3개를 글자로 표시한다.
  - 시각 디자인(색 대비, 마크 크기, 축)은 구현 시 dataviz 가이드를 따른다.
- **근거**: 헌법 기술 제약(런타임 의존성 0), 스펙 가정("앱이 직접 그린다, 확대·이동 없음").
- **대안**: Chart.js·uPlot은 의존성 추가라 기각했다. canvas는 접근성·테마 전환이 불리해 기각했다.

### S9. 차트 접근성

- **결정**:
  - SVG는 `role="img"`와 요약 `aria-label`을 가진다. 예: "벤치 프레스 추정 1RM, 4주 동안 80kg에서 87.5kg로 증가".
  - 같은 데이터를 `<details>` 안의 표("표로 보기")로 제공한다(FR-013).
  - 점 고르기: 차트 영역은 `tabindex=0`이고, ←/→로 점을 옮긴다. 터치·클릭은 가장 가까운 x의 점을 고른다. 고른 점의 날짜·값·세트는 차트 아래 `aria-live="polite"` 영역에 글로 나온다(US1-2).
  - 색만으로 구분하지 않는다. 달력의 운동한 날은 색과 점(•)으로 표시하고, 버튼 이름은 "11월 3일, 운동함 1회"다.
- **근거**: 헌법 I·FR-013·SC-004(axe 0건, 두 테마).

### S10. 진행 화면에서 차트 열기

- **결정**: 진행 화면 "기록" 안의 "차트 보기"는 전체 화면 `<dialog>`(가이드 시트와 같은 방식)로 종목 차트를 연다. 세션 상세·종목 이력의 "차트"는 `#/stats/exercise/:id` 화면으로 이동한다. 종목 차트 내용은 한 컴포넌트(`exercise-chart-view.ts`)를 두 곳에서 쓴다.
- **근거**: FR-011·SC-003. 대화상자는 진행 화면 DOM·입력값·타이머를 그대로 둔다(기능 2 G8과 같은 이유).

### S11. 하단 탭 5개

- **결정**: 탭은 루틴·기록·통계·가이드·설정 순서다. `Screen.tab`에 `'stats'`를 더한다. 320px에서 탭 하나는 64px이고 글자 2자라 들어간다.
- **근거**: 스펙 가정. 기존 탭 스타일(텍스트 + 현재 표시)을 그대로 쓴다.

### S12. 그날 기록으로 가기

- **결정**: 달력에서 운동한 날을 누르면, 세션이 하나면 `#/history/:id`로, 여럿이면 `#/stats/day/YYYY-MM-DD`(그날 세션 목록, 기록 목록과 같은 카드)로 간다.
- **근거**: US4-2. 기록 목록 화면에 날짜 필터를 넣는 것보다 작은 새 화면이 단순하다.
