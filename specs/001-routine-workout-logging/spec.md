# Feature Specification: 운동 루틴 관리 및 세트 기록

**Feature Branch**: `001-routine-workout-logging`

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "사용자가 직접 운동 루틴을 구성하고, 운동 세션 중 세트·무게·횟수를 빠르게 기록하며(이전 값 자동 채움, 오프라인 지원), 과거 기록을 조회할 수 있는 운동 기록 및 루틴 관리 기능"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 루틴 만들기 및 관리 (Priority: P1)

사용자는 자신만의 운동 루틴(예: "가슴·삼두 day")을 만들고, 운동 종목을 추가·순서 변경·삭제하며, 각 종목의 목표 세트 수를 설정한다. 만든 루틴은 수정·복제·삭제할 수 있다.

**Why this priority**: 루틴이 있어야 세션을 시작할 수 있으므로 모든 기록 기능의 출발점이다.

**Independent Test**: 루틴을 새로 만들고 종목 3개를 추가한 뒤 앱을 다시 열어도 루틴이 그대로 남아 있는지 확인하면 단독으로 검증되며, 계획을 저장하는 가치를 제공한다.

**Acceptance Scenarios**:

1. **Given** 루틴이 하나도 없는 사용자, **When** 이름을 입력하고 종목 3개를 추가해 저장하면, **Then** 루틴 목록에 해당 루틴이 3개 종목과 함께 표시된다.
2. **Given** 저장된 루틴, **When** 종목 순서를 바꾸거나 종목을 삭제하고 저장하면, **Then** 변경된 구성이 그대로 반영된다.
3. **Given** 저장된 루틴, **When** 복제를 선택하면, **Then** 같은 구성의 새 루틴이 생성되고 원본은 변하지 않는다.
4. **Given** 저장된 루틴, **When** 삭제를 확인하면, **Then** 루틴은 목록에서 사라지지만 과거 운동 기록은 유지된다.

---

### User Story 2 - 운동 세션 중 세트 기록 (Priority: P1)

사용자는 루틴으로 운동 세션을 시작하고(또는 루틴 없이 빈 세션을 시작하고), 각 종목에 세트별 무게와 횟수를 기록한다. 직전 세션의 값이 미리 채워져 있어 최소한의 조작으로 기록을 완료하며, 세트를 추가·수정·삭제하고 세션을 종료할 수 있다.

**Why this priority**: 운동 기록은 앱의 핵심 가치이며, 이후 통계·성장 차트의 데이터 원천이다.

**Independent Test**: 루틴으로 세션을 시작해 세트 여러 개를 기록하고 종료하면, 세션이 저장되고 목록에서 확인되는지로 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 이전에 같은 종목을 기록한 적이 있는 사용자, **When** 세션에서 해당 종목을 열면, **Then** 직전 세션의 무게·횟수가 입력 칸에 미리 채워져 있고 확인 한 번으로 세트를 완료할 수 있다.
2. **Given** 진행 중인 세션, **When** 세트를 추가하거나 값을 수정·삭제하면, **Then** 즉시 화면에 반영된다.
3. **Given** 진행 중인 세션, **When** 세션 종료를 선택하면, **Then** 총 운동 시간과 완료한 세트 수 요약이 표시되고 기록이 저장된다.
4. **Given** 루틴이 없는 사용자, **When** 빈 세션을 시작하고 종목을 즉석에서 추가하면, **Then** 루틴 없이도 기록할 수 있다.

---

### User Story 3 - 오프라인에서도 기록 보존 (Priority: P2)

네트워크가 불안정한 헬스장에서도 사용자는 기록을 입력할 수 있고, 앱을 닫거나 새로고침해도 진행 중인 세션과 입력값이 유실되지 않는다.

**Why this priority**: 헌법의 데이터 무결성 원칙에 따른 필수 신뢰 요건이지만, 기록 기능 자체가 있어야 의미가 있다.

**Independent Test**: 네트워크를 끊은 상태에서 세션을 기록하고 앱을 새로고침해도 입력 내용이 그대로 남아 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 네트워크가 끊긴 상태, **When** 세트를 기록하면, **Then** 오류 없이 저장되고 정상 사용할 수 있다.
2. **Given** 진행 중인 세션, **When** 앱을 닫았다가 다시 열면, **Then** 진행 중이던 세션이 복원되어 이어서 기록할 수 있다.

---

### User Story 4 - 과거 기록 조회 (Priority: P2)

사용자는 날짜별로 완료한 운동 세션 목록을 보고, 특정 세션을 열어 종목별 세트·무게·횟수를 확인하며, 필요하면 기록을 수정하거나 삭제한다. 종목별 이전 기록도 확인할 수 있다.

**Why this priority**: 기록을 되돌아봐야 점진적 과부하를 계획할 수 있으며, 후속 성장 차트 기능의 기반이 된다.

**Independent Test**: 세션 2개를 저장한 뒤 기록 화면에서 날짜순으로 보이고 상세 내용이 입력값과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 완료된 세션들, **When** 기록 화면을 열면, **Then** 최신순으로 날짜·루틴명·총 볼륨 요약이 표시된다.
2. **Given** 세션 상세 화면, **When** 세트 값을 수정하면, **Then** 수정된 값이 저장되고 목록 요약에도 반영된다.
3. **Given** 특정 종목, **When** 종목 이력을 열면, **Then** 해당 종목의 과거 세트 기록을 날짜순으로 볼 수 있다.

---

### Edge Cases

- 무게 0(맨몸 운동) 또는 소수점 무게(예: 2.5), 횟수 0·음수·비정상적으로 큰 값은 어떻게 처리되는가? → 무게는 0 이상의 소수 허용, 횟수는 1 이상 정수만 허용하고 범위를 벗어나면 입력 단계에서 안내한다.
- 세션 진행 중 앱이 강제 종료되면? → 마지막 입력 시점까지 복원된다.
- 오래 방치된 진행 중 세션은? → 다음 실행 시 이어하기 또는 종료·폐기를 선택하게 한다.
- 루틴을 삭제해도 그 루틴으로 기록된 과거 세션은 어떻게 표시되는가? → 기록은 유지되고 당시 루틴명으로 표시된다.
- 같은 종목이 한 세션에 여러 번 추가되면? → 허용하며 각각 독립된 항목으로 기록한다.
- 무게 단위(kg/lb) 변경 시 기존 기록은? → 저장 값은 변환 없이 보존하고 표시 단위만 바꾸는 방식으로 일관성을 유지한다.
- 세트를 하나도 완료하지 않고 세션을 종료하면? → 저장 여부를 확인하고, 저장하지 않으면 폐기한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 이름이 있는 운동 루틴을 생성, 수정, 복제, 삭제할 수 있어야 한다.
- **FR-002**: 사용자는 루틴에 운동 종목을 추가·삭제·순서 변경하고 종목별 목표 세트 수를 설정할 수 있어야 한다.
- **FR-003**: 시스템은 운동 종목 목록을 제공하고, 사용자가 직접 종목을 만들 수 있어야 한다.
- **FR-004**: 사용자는 루틴으로 또는 빈 상태로 운동 세션을 시작할 수 있어야 한다.
- **FR-005**: 사용자는 세션 중 종목별로 세트의 무게와 횟수를 기록하고, 세트를 추가·수정·삭제하며 완료 표시를 할 수 있어야 한다.
- **FR-006**: 시스템은 같은 종목의 직전 세션 값을 무게·횟수 입력 칸에 미리 채워야 한다.
- **FR-007**: 시스템은 입력값을 검증하고(무게 ≥ 0, 횟수 ≥ 1 정수) 잘못된 값에 대해 즉시 안내해야 한다.
- **FR-008**: 시스템은 세션 종료 시 운동 시간, 완료 세트 수, 총 볼륨(무게×횟수 합계) 요약을 보여주어야 한다.
- **FR-009**: 시스템은 입력 즉시 기기에 저장하여 네트워크 없이도 모든 기록 기능이 동작해야 하며, 앱 재실행 후 진행 중 세션을 복원해야 한다.
- **FR-010**: 사용자는 완료된 세션을 날짜순으로 조회하고, 상세에서 세트를 수정하거나 세션을 삭제할 수 있어야 한다.
- **FR-011**: 사용자는 종목별 과거 세트 기록을 조회할 수 있어야 한다.
- **FR-012**: 사용자는 무게 단위(kg/lb)를 선택할 수 있어야 하며, 기존 기록은 선택한 단위로 올바르게 표시되어야 한다.
- **FR-013**: 삭제된 루틴이 있어도 과거 세션 기록은 유지되어야 한다.
- **FR-014**: 사용자는 자신의 운동 기록을 내보내고 모든 데이터를 삭제할 수 있어야 한다.
- **FR-016**: 시스템은 기록을 사용자의 홈서버에 저장하고, 서버에 연결할 수 없을 때 기기에 쌓은 기록을 연결 복구 시 자동으로 서버에 반영해야 하며, 이 과정에서 기록이 유실되거나 중복되어서는 안 된다.
- **FR-017**: 시스템은 소유자 외의 접근을 차단해야 한다.
- **FR-015**: 모든 화면은 모바일 한 손 조작에 적합해야 하며, 로딩·빈 상태·오류 상태를 명시적으로 표시해야 한다.

### Key Entities

- **운동 종목(Exercise)**: 이름, 대상 부위, 기본/사용자 정의 여부. 이후 가이드 콘텐츠와 연결될 수 있다.
- **루틴(Routine)**: 이름, 순서가 있는 종목 구성(종목별 목표 세트 수).
- **세션(Session)**: 시작·종료 시각, 사용된 루틴(선택), 진행 상태(진행 중/완료), 종목별 기록의 집합.
- **세트 기록(Set Entry)**: 소속 세션과 종목, 순서, 무게, 횟수, 완료 여부.
- **사용자 설정(Preferences)**: 무게 단위 등 표시 설정.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이전 기록이 있는 종목에서 사용자는 한 세트를 5초 이내에 기록할 수 있다.
- **SC-002**: 신규 사용자는 앱을 처음 연 후 3분 이내에 첫 루틴을 만들고 첫 세션을 시작할 수 있다.
- **SC-003**: 네트워크 연결이 없는 상태에서 진행한 세션의 기록이 앱 재실행 후에도 100% 보존된다.
- **SC-004**: 사용자의 90%가 안내 없이 루틴 생성부터 세션 종료까지 첫 시도에 완료한다.
- **SC-005**: 기록 화면에서 과거 세션 목록이 사용자에게 체감 지연(1초 이내) 없이 표시된다. 세션 500개 기준이다.
- **SC-007**: 오프라인에서 기록한 세션이 홈서버 연결 복구 후 중복·누락 없이 100% 반영되고, 다른 기기에서도 같은 기록이 보인다.
- **SC-006**: 사용자가 입력한 값과 저장·표시된 값이 100% 일치한다(소수점 무게 포함).

## Assumptions

- 이 앱은 소유자 한 명만 쓰는 개인용 앱이며, 다중 사용자·회원가입·공개 서비스는 범위 밖이다.
- 데이터 저장과 배포는 사용자의 홈서버에서 이루어진다. 기록의 기준 저장소는 홈서버이며, 외부 클라우드 서비스에 의존하지 않는다.
- 헬스장에서는 홈서버에 닿지 않을 수 있으므로 기기 내 임시 저장 후, 홈서버에 연결되면 자동으로 동기화한다.
- 홈서버 배치, 기기 등록(일회용 코드로 기기 페어링), 집 밖 접속(VPN), 오프라인 우선 동기화 방식은 사용자의 기존 todo-app(`~/Documents/todo-app`)과 같은 방식을 따른다. 구체적 설계 재사용 범위는 계획 단계에서 정한다.
- 접근 보호는 소유자 한 명을 위한 기기 등록 방식으로 충분하며, 등록되지 않은 기기는 접근할 수 없다.
- 주 사용 환경은 모바일 브라우저이며, 같은 소유자가 여러 기기(폰, PC)에서 접속할 수 있다.
- 기본 운동 종목 목록은 주요 부위별 일반 종목을 앱이 기본 제공하며, 운동 GIF·3D 가이드 연결은 후속 기능(2번)에서 다룬다.
- 성장 차트·통계 대시보드는 후속 기능(3번)이며, 이 기능에서는 세션 요약과 종목별 이력 조회까지만 제공한다.
- Apple Watch·HealthKit 연동(심박수, 칼로리 등)은 이 기능의 범위 밖이다.
- 휴식 타이머, 슈퍼세트, 운동 공유·소셜 기능은 범위 밖이다.
- 기본 무게 단위는 kg이며, 설정에서 lb로 바꿀 수 있다.
